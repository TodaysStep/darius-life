## Blocking the very first successful deploy

1. **`PROTECTED_STRINGS` is still not actually set.** Confirmed directly in
   the latest GitHub Actions run (`136d76e`, run `36345771666`): the
   workflow's own `env:` log dump for the `npm run build` step shows
   `PROTECTED_STRINGS:` with nothing after it. A correctly-resolved secret
   shows as `***` there, not blank — a blank value there means no secret by
   that exact name exists in a scope this plain (non-environment-scoped)
   workflow can see. Set it at:
   - `TodaysStep/darius-life` → Settings → Secrets and variables →
     **Actions** → **Repository secrets** (not Environment secrets,
     Dependabot secrets, or Codespaces secrets — those are separate stores
     and won't resolve here) → New repository secret: `PROTECTED_STRINGS`,
     your mailing address and phone number, one per line.

   This is the only thing currently failing the build. Every other check —
   including the two new v2.1 checks (17: no `legal/private` path ever
   tracked in git or generated into `dist/`; 18: `deploy.yml` has a
   live-verification job that can actually fail the workflow) — passes.
