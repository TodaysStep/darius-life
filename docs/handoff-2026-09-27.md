## Still open

1. **The other 4 security headers** (Content-Security-Policy, Referrer-Policy,
   Permissions-Policy, X-Frame-Options) need a Response Header Transform
   Rule. This needs Cloudflare's **Rulesets** API permission — the token in
   use as of this update can edit zone settings but got `"Authentication
   error"` on `/rulesets`, `/dns_records`, `/access/apps`, and
   `/purge_cache`. Either add those permissions to the existing token, or do
   it from the dashboard: Rules → Transform Rules → Response Header
   Transform Rule, using the header list in `cloudflare/rules.md`.
2. **`darius.life/control/*` needs to be added to the existing Access
   application** as a second covered path (alongside `/legal/private/*`) —
   needs the Access API permission, same gap as above. Until this is done,
   `/control/*` fail-closes safely on its own (confirmed), but Access itself
   isn't the one stopping an unauthenticated request yet.
3. **Web Analytics / Browser Insights** — not confirmed off. No accessible
   endpoint found with the current token to check or change this.
   `checks/live.mjs` caught an intermittent `cloudflareinsights` beacon
   script on 2026-09-27, consistent with one of these being on. Dashboard:
   Analytics & Logs → Web Analytics, and Speed → Optimization → Browser
   Insights — turn both off.
4. **Cache purge** — not accessible with the current token either. Not
   currently blocking anything known, but worth a "Purge Everything" once
   the Transform Rule is added, in case any edge node cached a response from
   before it existed.
5. **The `darius-life-confidential` Worker** — a leftover from the earlier,
   superseded confidential-subdomain architecture. Nothing in the current
   repo references it. Safe to delete; not deleted yet pending a yes.
6. **Branch protection on `main`** requiring the `build` job to pass (brief
   section 9.1) — no tool used so far reaches this; needs a human in
   GitHub's own Settings UI, or a token with repo administration rights.

## A note on the token in use right now

Whatever's connected as the `Cloudflare API` credential right now can: list
zones, read/edit zone settings, read Workers Routes, and (via the separate
Cloudflare Developer Platform connector) manage Workers/R2/KV/D1. It
cannot: read or write DNS records, Access applications, Rulesets (Transform/
Redirect Rules), or purge cache. If those permissions get added to this same
token, items 1, 2, and 4 above become directly fixable the same way items
were fixed tonight — no dashboard needed.
