A shared language for how we build

01 · Runway

Can we sustain the mission?

Burn rate: how fast we spend money to build and operate. Runway: how long we can keep going at the current burn rate.

Track both. Plan ahead. Reduce scope, extend runway, or bring in more resources if needed.

02 · Development

How much change is entering the system?

Ramping up: building fast, adding features, growing the team. Locking down: reducing new changes to focus on reliability and safety.

Use the right speed for the moment. More change is helpful early. Stability becomes critical as we get closer to deployment.

03 · Flight

Make it solid, then launch it.

Stabilize: fix, test, strengthen. Deploy: release to real people. Verify: fly the route. Check it works.

Find and fix issues. Deploy to production. Verify real journeys, not just server responses.

04 · Ready

Make it strong enough for real life.

Harden: prepare for ordinary reality—load, interruptions, older devices, unexpected input, and time. Durable: built on proven, resilient infrastructure. Fewer single points of failure.

Test under real conditions. Monitor and respond. Keep it maintainable. Reduce ongoing cost and complexity.

05 · Destination

Keep it open for everyone.

Free access: build systems that anyone can access—no paywall. Hosting with Cloudflare (free tier). Domain fees only (manageable, yearly).

This is the destination, not a pricing feature. Durability makes free access possible.

Know the state of the system.

However inconvenient, everyone should know where we actually are.

Real tools. Real people. Real systems. Real access.
